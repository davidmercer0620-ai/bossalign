# 02：证据、规则状态与确认

BossAlign 保存原始反馈事件，并记录规则来自用户明确指令、用户偏好、AI 推断还是未验证假设。解析结果始终先进入 `draft`，即使 Provider 返回较高置信度也不会自动生效。

| 状态 | 含义 | 是否参与任务检索 |
| --- | --- | --- |
| `draft` | 解析建议，等待人工核对 | 否 |
| `confirmed` | 经过显式确认的规则 | 满足置信度与范围条件时参与 |
| `inactive` | 已停用，历史仍保留 | 否 |

确认会检查规则置信度（默认至少 `0.60`），并记录确认人和新版本。低置信度规则应先通过 `update_rule()` 补齐/修正，再确认。`update_rule()` 和 `deactivate_rule()` 都创建不可覆盖的历史快照；原始反馈事件不会随规则停用而删除。

## 证据字段

事件保留原文、来源、审核人、时间和解析结果。规则引用事件 ID，并记录原始反馈、适用范围、反例边界、置信度、状态和版本。来源和推断类型分开存储：模型可以提出解释，但不能替代用户确认。

## 审核状态

确定性检查只对规则中显式配置的精确短语做扫描；模型审核标记为 `llm_inference`。不管是哪种模式，`user_approved` 都保持 `false`。系统检查没有发现问题，不代表真实审核人已经批准。

# 白皮书 01：反例边界（Negative Boundary）—— 终结大模型的过度拟合

> **作者**：BossAlign 架构组  
> **核心命题**：为什么大模型在接收人类反馈后，总是会走向另一个极端？如何用“反例边界”实现真正的精准对齐？

---

## 1. 现象：大模型的“幼稚化过度纠错”

在真实的组织审稿中，人类创作者常遇到以下现象：

- **场景 A**：领导审阅了关于“展厅选品”的视频脚本，反馈道：*“这篇是给服装采购商挑面料的，别在这里花大篇幅讲织造车间的大圆机怎么调张力，买家不关心这个。”*
- **传统大模型的错误反应**：
  大模型把这条反馈总结为一条全局 Prompt 禁令：`[Never mention weaving machinery or factory processes]`。
  结果，在下一篇专门展示**“工厂硬核制造实力与研发”**的视频脚本里，大模型直接把所有机器和工艺删得一干二净，被领导再次痛骂。

这就是经典的 **过拟合与过度泛化（Over-correction / Hallucinated Generalization）**。大模型无法区分**“局部场景下的减法”**与**“全局体系的禁忌”**。

---

## 2. 解决方案：三位一体的边界守卫模型

在 `BossAlign` 架构中，**任何一条从人类反馈中提炼出的原则，必须强制具备三个字段**，缺少任何一个，该原则视为无效规则（Invalid Rule）：

```text
┌────────────────────────────────────────────────────────┐
│                   BossAlign 规则数据结构                │
├────────────────────────────────────────────────────────┤
│ 1. Core Directive (核心主张)                           │
│    - 提取出的正面或负面倾向动作                          │
├────────────────────────────────────────────────────────┤
│ 2. Applicable Scope (适用条件)                         │
│    - 适用的篇目类型、目标受众、叙事目的                  │
├────────────────────────────────────────────────────────┤
│ 3. Negative Boundary / Counter-Example (反例与禁止跨界) │
│    - 明确列出【何时绝对不允许套用此规则】                │
└────────────────────────────────────────────────────────┘
```

### 实战示例：

```json
{
  "rule_id": "RULE-SCOPE-042",
  "reviewer": "Boss_Victor",
  "directive": "减少宏观产线讲解，聚焦在产品成型后的握持感与便携性",
  "applicable_scope": {
    "topic_types": ["消费级产品开箱", "门店选型指南"],
    "target_audience": ["普通消费者", "初级经销商"]
  },
  "negative_boundary": {
    "prohibited_topics": ["工业级巡检机交付", "国家级实验室研发实力"],
    "rationale": "对于专业B2B或科研客户，设备规格与制造公差是核心信任基石，严禁删减！"
  }
}
```

## 3. 动态召回机制：基于目的（Intent）而非关键词

当系统收到新的生成任务时，检索器（Retriever）的工作逻辑不是暴力检索所有带“工艺”或“机器”的规则，而是执行**两阶段过滤**：

1. **第一阶段：目的对齐过滤（Intent Filtering）**
   检查新任务的 `topic_type` 和 `audience` 是否命中 `applicable_scope`。若未命中，直接忽略该规则。
2. **第二阶段：反例碰撞检测（Boundary Clash Check）**
   检查新任务是否触碰了某条规则的 `negative_boundary`。若触碰，强制发出警报，并在生成提示中显式下发保护指令：
   `[SYSTEM WARNING]: Do NOT apply RULE-SCOPE-042 here. Retain full engineering specs.`

通过这种方式，AI 永远不会在 A 方案里长了记性，却在 B 方案里犯下蠢病。
